# Стенд качества и режим во весь экран

## 1. Стенд `lw-tune.html`

Отдельная страница, не трогает SmartHome:

```
http://<адрес-сервера>:3000/lw-tune.html
```

Движок держит рычаги в `localStorage` под ключом `lw.quality.v1`, а он общий на
весь адрес. Покрутил здесь — открыл `index mini.html`, там уже то же самое.
Переносить руками не надо.

### Верхняя строка

```
low 320x240 ÷2 · 14.8 fps · 3.4 мс · сбросов 0
September - Seascape - Cloudy · аним 6.8% / бокс 13% · 17:05
```

| Поле | Смысл |
| --- | --- |
| `14.8 fps` | фактический FPS за последнюю секунду; должен быть близок к заданному |
| `3.4 мс` | реальная цена кадра; цель — меньше половины `1000/FPS` |
| `сбросов 0` | сколько раз сторож сам понизил профиль; больше нуля = не вывозит |
| `аним 6.8%` | доля пикселей, которые вообще шевелятся (свойство сцены) |
| `бокс 13%` | доля кадра, которую реально отдаём в canvas — главная экономия |

Бюджет кадра при 15 FPS — 66 мс, значит цель порядка 33 мс. Остаток нужен
самому SmartHome: часы, опрос `/api/mini/data`, перерисовка текста.

### Кнопка АВТОТЕСТ

Замеряет цену кадра (цикл палитры + рендер + блит) для всех делителей:

```
дел.  буфер     аним%  бокс%  мс     максFPS
÷1    640x480    6.8    13     41.2   24
÷2    320x240    6.8    13     11.4   87
÷3    213x160    7      14.5   5.6    178

бери ÷2 (320x240) при 15 FPS · запас по мощности x5
```

Рекомендация — самый крупный буфер с двойным запасом. Запас нужен потому,
что Асе падает не сразу, а к десятой минуте, когда включается сборщик мусора.

Жми АВТОТЕСТ на самом телефоне — на ноуте он покажет нули. Замер `÷1`
временно держит ~390 КБ буферов; если вкладка перезагружается — крути
рычаги вручную.

### Порядок настройки вручную

1. Сцена → `самая тяжёлая`. Это May Rain, 31 % шевелящихся пикселей — втрое
   больше среднего. Настроишь по ней — остальные 21 точно поедут.
2. Время → `03:00`. Ночное освещение — худший случай для читаемости текста.
3. Пиксели — от `÷2` вниз, пока фактический fps не сравняется с заданным.
4. Если даже `÷8` не тянет — снижай FPS, а не разрешение.
5. Последняя линия — Профиль → `still`: сцена замирает, но свет едет за
   реальным временем. Один кадр раз в 30 секунд.
6. Оставь на 15–20 минут. Критерий — `сбросов 0` и нет вылета. Если через
   15 минут в верхней строке другой профиль — выбор был слишком смелым.

### Рычаги

| Рычаг | Значения | URL | Что делает |
| --- | --- | --- | --- |
| Профиль | off / still / nano / ace / low / medium / high | `?lw=nano` | готовый набор всего остального |
| Пиксели | 1–8 | `?lwscale=4` | делитель разрешения буфера |
| FPS | 1–60 | `?lwfps=6` | предел частоты кадров |
| Свет | 1–900 с | `?lwtod=180` | как часто пересчитывать освещение |
| Сглаж. | выкл / вкл | `?lwblend=0` | плавное смешивание цветов в цикле |
| Блит | весь / только аним. | `?lwdirty=1` | отдавать в canvas только бокс анимации |
| Аним. | только свет / полная | `?lwanim=0` | полное отключение цикла палитры |
| Кроп | cover / contain / fill | `?lwfit=contain` | как вписать 4:3 в экран 2:3 |
| Время | реал. / 03:00 / … | — | только на стенде, замораживает часы |

Служебные: `?lwspeed=0.5` (скорость воды), `?lwdebug=1` (логи), `?lwfs=1`
(см. раздел 2).

### Два новых рычага

**Блит — только бокс анимации.** Конвертер знает, какие пиксели вообще
способны меняться. Движок считает их общий прямоугольник и отдаёт в canvas
только его. Сентябрьская сцена на `÷2`: бокс `74,158 203x49` — вместо
76 800 пикселей передаём 9 947, то есть 13 %. Небо и горизонт не трогаются,
потому что в оригинале они и не анимированы. Выключать стоит только если
вылезет артефакт.

**Анимация — только свет.** Цикл палитры отключается целиком. Кадр
считается только когда сдвинулось время суток; в промежутках движок спит
секундными таймерами. Пиксель-арт остаётся оригинальным, свет живой —
утро, день, закат, ночь сменяются по реальным часам. Не двигается только
вода и облака.

### Профили

| Профиль | FPS | Дел. | Буфер | Свет | Цикл | Когда |
| --- | --- | --- | --- | --- | --- | --- |
| `off` | — | — | — | — | — | фон выключен |
| `still` | 15 | ÷3 | 213x160 | 30 с | нет | крайний случай |
| `nano` | 6 | ÷4 | 160x120 | 180 с | есть | второй кандидат для Ace |
| `ace` | 10 | ÷3 | 213x160 | 120 с | есть | первый кандидат для Ace |
| `low` | 15 | ÷2 | 320x240 | 60 с | есть | текущий по умолчанию |
| `medium` | 20 | ÷2 | 320x240 | 30 с | + сглаж. | телефоны пободрее |
| `high` | 30 | ÷1 | 640x480 | 15 с | + сглаж. | ноут/планшет |

Сторож идёт вниз по цепочке `high → medium → low → ace → nano → still` и
останавливается там. До `off` он не доходит никогда — сам себя он не
выключит.

### Расход памяти по делителю

| Делитель | Буфер | Пикселей | Память сцены |
| --- | --- | --- | --- |
| ÷1 | 640x480 | 307 200 | ~390 КБ |
| ÷2 | 320x240 | 76 800 | ~98 КБ |
| ÷3 | 213x160 | 34 080 | ~44 КБ |
| ÷4 | 160x120 | 19 200 | ~25 КБ |
| ÷6 | 106x80 | 8 480 | ~11 КБ |
| ÷8 | 80x60 | 4 800 | ~6 КБ |

Сверх этого постоянно держится один оригинал 640x480 (307 КБ) и палитры.
Одновременно в памяти всегда только одна сцена.

### Те же рычаги внутри SmartHome

Долгое нажатие (1 секунда) на блок часов на главном экране. Там же кнопка
«Во весь экран». Никаких постоянных элементов в интерфейсе не добавлено.

## 2. Режим во весь экран в Firefox 31.0

Короткий ответ: кнопки в интерфейсе нет, но сам Fullscreen API в нём ЕСТЬ.
Gecko поддерживает `mozRequestFullScreen` с версии 9.0, а Firefox 31 — это
Gecko 31. Значит развернуть страницу по тапу можно.

### Способ 1 — штатный, рекомендуется

В движок вшито. Долгое нажатие на часы → «Во весь экран». Или вручную:

```js
LW.fullscreen()          // перебирает все варианты API
LW.exitFullscreen()
LW.isFullscreen()
```

Перебор идёт в порядке `requestFullscreen`, `mozRequestFullScreen`,
`webkitRequestFullscreen`, `webkitRequestFullScreen`, `msRequestFullscreen`.
В FF31 срабатывает второй. Прописная `S` в `mozRequestFullScreen` обязательна
— это частая ошибка. Без префикса API появился только в FF47.

Главное ограничение: вызов обязан быть изнутри настоящего тапа. Из
`setTimeout`, из `onload`, из консоли без жеста — молча не сработает.

### Способ 2 — автоматически по первому тапу

Открой `index mini.html?lwfs=1`. Первый тап в любом месте разворачивает
страницу, после чего слушатель снимается. Тап не блокируется — свайпы и
кнопки Tuya работают как обычно. Это удобно для киоска: браузер выходит из
полноэкранного режима при любой перезагрузке, а так достаточно одного тычка.

### Если не сработало — настройки about:config

Набери `about:config` в адресной строке:

| Параметр | Значение | Зачем |
| --- | --- | --- |
| `full-screen-api.enabled` | `true` | включает API вообще |
| `full-screen-api.allow-trusted-requests-only` | `false` | разрешает вызов без жеста |
| `full-screen-api.ignore-widgets` | `true` | помогает при артефактах рисования |
| `browser.chrome.dynamictoolbar` | `true` | прячет адресную строку при скролле |

После изменения перезагрузи страницу.

### Способ 3 — скролл-трюк (частично)

Старый приём: сделать документ выше вьюпорта и вызвать `window.scrollTo(0, 1)`
— адресная строка уезжает вверх. Полного экрана не даёт, но возвращает
~40 пикселей высоты.

На стенде он включён как запасной вариант. В `index mini.html` он НЕ
работает принципиально: там `body { position: fixed; overflow: hidden }`, то есть
скроллить нечего. Ломать эту вёрстку ради сорока пикселей не стоит —
сломаются свайпы между экранами.

### Способ 4 — ярлык на рабочем столе через WebRT

Самый чистый результат для киоска, если захочешь возиться. В FF31 есть
Android Web Runtime (его вырезали только в FF47). Кладёшь рядом
`manifest.webapp`:

```json
{
  "name": "SmartHome",
  "launch_path": "/index mini.html",
  "fullscreen": "true",
  "orientation": "portrait"
}
```

И ставишь через `navigator.mozApps.install('/manifest.webapp')`. Получается ярлык
без адресной строки вообще, без необходимости тапать после каждой
перезагрузки.

### Способ 5 — другой браузер

На Android 2.3 работают и имеют штатный пункт меню Fullscreen: Opera Mobile
12.1, Dolphin Browser, UC Browser. Это не Fullscreen API, а их собственный
режим окна, поэтому работает без всякого кода. Минус — другие движки и
другая производительность canvas, придётся перемерять рычаги заново.

### Про версию Firefox

Если на Асе Android 2.2 — 31.0 действительно потолок, но есть ещё 31.3.0esr
для ARMv6 с заплатками безопасности до января 2015:

```
https://ftp.mozilla.org/pub/mobile/releases/31.3.0esr/android-armv6/multi/
```

Если на аппарате Android 2.3 и ARMv7, то потолок — Firefox 47, а там уже
есть беспрефиксный `requestFullscreen` (за флагом
`full-screen-api.unprefix.enabled`) и заметно более быстрый canvas. Перебор
методов в `LW.fullscreen()` покрывает оба случая.

### Мета-теги

Полного экрана не дают, но убирают зум и паразитный скролл. В mini уже есть
`viewport`; на стенде добавлены также `mobileoptimized` и
`apple-mobile-web-app-capable`.

### После входа в полный экран

Движок сам подписан на `fullscreenchange`, `mozfullscreenchange`,
`webkitfullscreenchange`, `MSFullscreenChange` и пересчитывает геометрию canvas
дважды (через 60 и 400 мс) — старые сборки Gecko сообщают новый размер
окна с задержкой. Фон корректно дотянется до новых границ без перезапуска
рендерера.
